# 8. Sequencer and subscribeRepos firehose

Date: 2026-08-08

## Status

Accepted

## Context

The `repo_seq` table introduced in ADR-0002 has held the sequencer's persistence surface, but no service actually populated it, drained it, or exposed it. The atproto firehose (`com.atproto.sync.subscribeRepos`) is the public delivery channel for every repo event emitted by the PDS, and the four SQLite databases already split account, sequencer, DID-cache, and actor storage along the seams that ADR-0002 carved out. Until now, the only HTTP route the server actually served was `GET /metrics`; the typed-column discipline (`DbId` ULIDs, `Did`, `OffsetDateTime`) and the raw-SQL `RETURNING` tradeoffs called out in ADR-0006 left a clear seam for the sequencer to plug into.

The remaining pieces: a typed row mapper for the typed `repo_seq` columns, an event envelope that round-trips through the persistence layer and the on-wire JSON the firehose expects, a delivery channel that survives the gaps between actor commits and subscriber connects, a CBOR frame codec for the WebSocket, and a poem WebSocket handler that does cursor validation (FutureCursor rejection, OutdatedCursor reset) and a 30-second ping. The crawlers notify path (`Crawlers::notify_of_update`, called from the sequencer after every insert) belongs to this same seam because it shares the rate-limited outbound HTTP shape.

## Decision

1. **Typed `Sequencer` over the existing typed entity.** `pds/src/sequencer/mod.rs` defines `Sequencer { db: DatabaseConnection, crawlers: Crawlers, job_pool: Option<Arc<SqlitePool>>, last_seen: Option<DbId> }` and the four-arg constructor `Sequencer::new(db, crawlers, job_pool, last_seen)`. `curr`, `next_seq`, `earliest_after_time`, and `request_seq_range` build raw `Statement::from_sql_and_values` calls through `db.query_one_raw` / `db.query_all_raw`; `DbId` cursors bind as `sea_orm::Value::Bytes`, `OffsetDateTime` filters bind as RFC-3339 strings via `events::format_offset_datetime`. `repo_seq_from_row` re-hydrates the entity's typed columns from `sea_orm::QueryResult` and is the single row mapper used by every read path. `RequestSeqRangeOpts { earliest_seq, latest_seq, earliest_time, limit }` is the public filter shape; `seq`/`time` cursors are typed (`DbId` / `OffsetDateTime`).

2. **Typed `RepoSeqNew` insert model; `sequence_evt` mints the `DbId` locally.** Formatters (`format_seq_commit`, `format_seq_handle_update`, `format_seq_identity_evt`, `format_seq_account_evt`, `format_seq_sync_evt`, `sync_evt_data_from_commit`) return `RepoSeqNew` typed against `migration::types::{DbId, Did}` so `ActiveModel::insert(...).exec_with_returning` succeeds against the non-auto-increment `BLOB(16)` primary key. `sequence_evt` generates the `DbId` via `DbId::new()` before the insert (the entity model has no `last_insert_id` to recover), captures the returned `seq` for the broadcast, sets the `cacos_last_seq` gauge from the ULID timestamp in milliseconds, and invokes `Crawlers::notify_of_update` as a best-effort warn-on-failure side effect (sequencing must not block on a crawler). `sequence_commit` / `sequence_handle_update` / `sequence_identity_evt` / `sequence_account_evt` / `sequence_sync_evt` are the public sequencer entry points; `delete_all_for_user(did)` removes every `repo_seq` row for the DID.

3. **JSON envelope via `typed_seq_evt` + `serde_json::to_string`.** `typed_seq_evt(row)` reads the typed columns and decodes the `event: Vec<u8>` payload through `serde_ipld_dagcbor` into the matching `TypedCommitEvt` / `TypedSyncEvt` / `TypedIdentityEvt` / `TypedAccountEvt`, populates the `seq` field from `row.seq.0.timestamp_ms()` and the `time` field from `format_offset_datetime(row.sequenced_at)`, and returns the typed enum. `SeqEvt` is a custom-`Deserialize` enum that branches on the `type` field so envelopes stay untagged on the wire. The envelope is the only on-wire shape; the persistence layer sees `RepoSeq` rows with raw CBOR `event` blobs.

4. **Direct sqlx 0.8 delivery channel, not apalis-sql.** The worker shape (push one job per sequenced event, run a poller that publishes to a broadcast channel, mark the row done) is preserved from the reference implementation, but the on-disk schema (`apalis_seq_jobs`) and the poller are implemented against `sqlx_0_8::sqlite::SqlitePool` rather than the `apalis` / `apalis-sql` crates. `connect_jobs_db(path)` opens (or creates) the SQLite jobs DB with `services-fs`-style pragmas and runs `CREATE TABLE IF NOT EXISTS apalis_seq_jobs (id TEXT PRIMARY KEY, job_type TEXT, status TEXT, attempts INTEGER, max_attempts INTEGER, run_at INTEGER, payload TEXT)` so the layout matches what apalis-sql would create and the worker can be ported back to apalis-sql without a schema migration. `enqueue_seq_event_job(pool, job)` does `INSERT OR REPLACE` keyed by `seq-{ms}`; `run_seq_event_job` publishes the envelope, increments `cacos_seq_events_total`, and records `cacos_sequencer_poll_interval_seconds` (kind `publish`). `spawn_seq_event_worker(pool, broadcast)` runs the `Pending -> Done` poll loop on a dedicated tokio task and returns its `JoinHandle`. Producer and consumer share the same SQLite path so delivery is in-order.

5. **`SharedBroadcast` plus a typed `Outbox` replace the rsky `EVENT_EMITTER`.** `pds/src/sequencer/apalis_worker.rs` exports `SharedBroadcast { tx: tokio::sync::broadcast::Sender<String> }` (Clone, derived for `poem::Route::data`). `pds/src/sequencer/outbox.rs` defines `Outbox { caught_up, last_seen, cutover_buffer, sequencer, backfill_cursor, broadcast }` plus `OutboxOpts { max_buffer_size }` (default 500, matching the reference's `MAX_BUFFER` / `PAGE_SIZE`). `Outbox::events(backfill_cursor)` first runs the cutover backfill from `repo_seq` via `request_seq_range`, then drains the broadcast channel and yields `SeqEvt` values; a slow subscriber gets `max(0, curr - last_seen)` recorded against `cacos_outbox_buffer_lag` on every iteration. The broadcast replace is intentional: rsky's `EVENT_EMITTER` poll loop is not ported.

6. **CBOR frame codec at `pds/src/sequencer/ws_frames.rs`.** On-wire format is two DAG-CBOR objects back to back: the header `MessageFrameHeader { op: FrameType, t: Option<String> }` or `ErrorFrameHeader { op: FrameType }`, followed by the body. `FrameType` is `repr(i8)` via `serde_repr`, with `Message = 1` and `Error = -1`, so a node can branch on the first byte. `MessageFrame<T>` wraps `(header, body)` and emits `CBOR(header) ++ CBOR(body)`; `ErrorFrame` carries `ErrorFrameBody { error: String, message: Option<String> }` and the `FutureCursor` / `NextError` / `CurrError` / `SerializationError` / `EarliestAfterTimeError` codes used by the route. `InfoFrameBody { name, message }` carries the `OutdatedCursor` message with `t = "#info"`. The discriminator string for message bodies is `"#commit"`, `"#identity"`, `"#account"`, `"#sync"`, or `"#info"`.

7. **poem WebSocket handler with cursor validation and 30s ping.** `pds/src/xrpc/com/atproto/sync/subscribe_repos.rs` exposes `pub async fn subscribe_repos(ws: WebSocket, Query(query): Query<SubscribeReposQuery>, state: &State<SharedSequencer>, broadcast: &State<SharedBroadcast>) -> impl IntoResponse`. The handler reads `cursor: Option<i64>` (treated as a `timestamp_ms` surrogate on the wire), fetches `next_seq` and `curr` from the inner sequencer, and emits: an `ErrorFrame { error: "FutureCursor" }` when `cursor > curr.unwrap_or(0)`; an `#info` `MessageFrame { name: "OutdatedCursor" }` followed by `cursor = earliest_after_time(3-days-ago).seq.unwrap() - 1` when the requested backfill predates the 3-day window (`REPO_BACKFILL_LIMIT_MS = 3 * 24 * 60 * 60 * 1000`); otherwise the requested cursor. The body conversion branches over `SeqEvt` and emits `SubscribeReposCommit` / `SubscribeReposIdentity` / `SubscribeReposAccount` / `SubscribeReposSync` lexicon structs (using `from_str_to_utc` to decode the typed time) inside `MessageFrame<T>` with the right discriminator. The loop `tokio::select!`s between `event_stream.next()`, the WebSocket inbound stream (`Pong` on `Ping`, break on `Close`), and a 30-second `tokio::time::interval` that emits `Message::ping(vec![])`.

8. **`Crawlers` notifies subscribed relays, rate-limited to 20 minutes.** `pds/src/sequencer/crawlers.rs` holds `Crawlers { hostname, crawlers, last_notified }`; `notify_of_update` reads `SystemTime::now()` in milliseconds, no-ops if `now - last_notified < 20 * 60 * 1000`, otherwise fans out `POST {service}/xrpc/com.atproto.sync.requestCrawl` with `CrawlerRequest { hostname }` via `futures::stream::iter(...).then(...)`. The user agent is built at compile time from `CARGO_PKG_HOMEPAGE` / `CARGO_PKG_NAME` / `CARGO_PKG_VERSION` (constant `APP_USER_AGENT`).

## Consequences

- The sequencer ships 17 tests (`cargo test -p cacos-pds sequencer::`): 5 events, 2 apalis worker, 2 crawlers, 3 sequencer mod, 3 outbox, 2 ws_frames. The subscribe-repos route ships 5 tests: 2 byte-level frame-shape assertions (`future_cursor_is_rejected_with_error_frame`, `info_frame_for_outdated_cursor_carries_correct_discriminator`), `subscribe_repos_query_default_cursor_is_none`, and 2 end-to-end TCP roundtrip tests (`subscribe_repos_roundtrip_streams_commit_backfill_then_identity_live`, `subscribe_repos_roundtrip_rejects_future_cursor_with_error_frame`) that boot a real `poem::Server` on an ephemeral port, drive the apalis-backed delivery pipeline over a shared jobs DB, and read binary frames through `tokio_tungstenite`. The full workspace is 228 tests, 0 failures.

- The `apalis` / `apalis-sql` crates are not added to `Cargo.toml`; the worker uses `sqlx_0_8::sqlite` directly with the `apalis_seq_jobs` schema. If a future reader wants to swap the worker for `apalis-sql`, only `pds/src/sequencer/apalis_worker.rs` changes — the schema and the `SeqEventJob` shape are already correct.

- `cacos_last_seq` (gauge) is populated from `DbId::timestamp_ms()` so its value is the ULID millisecond timestamp of the last insert, not a monotonic integer. `cacos_seq_events_total` (counter) and `cacos_sequencer_poll_interval_seconds` (histogram, label `kind` = `publish` / `poll`) populate from the worker. `cacos_outbox_buffer_lag` (gauge) populates from the `Outbox` live loop. All four were registered as constants in `pds/src/observability/metrics.rs` before this work landed.

- The `Outbox` is intentionally not derived `Clone`. The route clones the inner `Sequencer` (which is `Clone`) at handler entry; the `Outbox` is constructed per-connection so each subscriber gets its own `last_seen`, `cutover_buffer`, and broadcast receiver.

- `sequence_account_evt(did, active, status)` takes a `rsky_lexicon::com::atproto::sync::AccountStatus` directly rather than the internal `crate::account::helpers::account::AccountStatus`. The caller is expected to convert at the boundary; the routing goes through `format_seq_account_evt` which renders `active: bool` plus an optional `status: Option<LexiconAccountStatus>` into the typed `AccountEvt`.

- `format_seq_commit` continues to delegate to `rsky_repo::car::blocks_to_car_file` so the on-disk and on-wire commit blocks remain byte-compatible with the reference. The typed `OffsetDateTime` boundary is at `events::format_offset_datetime` only; the JSON envelope carries an RFC-3339 millisecond-precision Z-suffixed string.

- Two known follow-ups: the `sequencer::outbox::tests::events_backfills_from_cursor_then_continues_live` test is timing-flaky on machines where two inserts land in the same millisecond (the assertion compares `evt.seq()` to the next cursor; two ULIDs generated in the same ms yield equal `timestamp_ms`). The flake pre-dates this work and is independent of the route. The TCP roundtrip tests pin `tokio-tungstenite = "0.27"` to match the tungstenite version poem itself uses; any future bump of `poem` should re-check this pin.
