# 10. PDS observability sweep

Date: 2026-08-09

## Status

Accepted

## Context

ADR-0003 established the tracing registry, the Prometheus recorder, the `cacos_` metric namespace, and the p50/p90/p99 latency reporter. It landed only the foundation: dimensional stage labels, a stable timed-stage histogram, a recorder race fix, and the in-flight instrumentation that consumes them. The pieces that were still missing were the tail-latency gauges (p999 and max), a `timed()` helper to make the instrumentation trivial at call sites, the per-subsystem stage timings, the firehose lag gauge that ADR-0008 claimed but never wired up, real `com.atproto.repo.*` write handlers (the only place the stage histogram would actually get populated on the write path), and a `tracing-unwrap` adoption at the process-startup boundary so a failed init shows up in the structured log instead of just panicking.

## Decision

1. **p999 and max inter-event timing gauges.** `pds/src/observability/timing.rs`'s `report_timings` now folds `histogram.value_at_quantile(0.999)` and `histogram.max()` alongside the existing p50/p90/p99 fold and emits `cacos_timing_p999_seconds` / `cacos_timing_max_seconds` with the same `span` / `event` labels. The `timing histogram snapshot` info log picks up `p999_ms` and `max_ms` fields. The single-statement invariant `max >= p999 >= p99 >= 0` is preserved by the histogram construction (`Histogram::new_with_max(1_000_000_000, 2)`).

2. **`cacos_timing_seconds` stage histogram with a static vocabulary.** `pds/src/observability/metrics.rs` registers the histogram name and the `describe_histogram!` with the `Unit::Seconds`/`Stage timing histogram, labeled by stage` HELP string. The vocabulary is a finite set of static `&'static str` labels incremented through the `metrics::histogram!` / `metrics::gauge!` / `metrics::counter!` macros; spans, DIDs, CIDs, NSIDs, filenames, and error strings are never accepted as stage values. The document divides the boundaries into:
   - `auth` — central JWT verification in `validate_access_token`.
   - `repo_load`, `repo_write`, `seq_write` — the three XRPC repo write handler boundaries.
   - `seq_poll`, `seq_publish`, `outbox_events` — the firehose side.
   - `blob_put`, `blob_get` — the blob store I/O boundaries.
   - `actor_get_blocks`, `actor_root_write`, `actor_blocks_put`, `actor_blocks_delete`, `actor_apply_commit`, `actor_cache_evict` — the actor store repo storage boundaries. `actor_apply_commit` is a single coarse stage that wraps the whole transaction (`apply_commit` does the root update and the block insert/delete inside one SeaORM transaction; we cannot split the transaction without breaking atomicity, so the fine-grained labels are recorded inside the closure with `metrics::histogram!` directly).
   - `repo_load` / `repo_write` / `seq_write` are reserved for the future write path that needs them.

3. **`timed(stage, fut)` async helper.** `pds/src/observability/timing.rs` exports `pub async fn timed<T>(stage: &'static str, fut: impl std::future::Future<Output = T>) -> T`. The helper opens a `cacos.stage` span, emits two `tracing::info!` events inside (`start` and `end`), measures wall-clock duration, records one `cacos_timing_seconds{stage="…"}` observation, and returns the wrapped future's output unchanged. It never converts, swallows, or logs errors. Internally it uses `tracing::Instrument::instrument(fut, span.clone())` so the future's events are also associated with the span (the `TimingLayer` then captures the inter-event interval between `start` and `end` as a sample into the p50/p90/p99/p999/max gauges).

4. **Repo write handler instrumentation.** `pds/src/xrpc/com/atproto/repo/{create_record, put_record, apply_writes, delete_record, upload_blob, describe_repo}.rs` wrap the three boundaries with `timed("repo_load", …)`, `timed("repo_write", …)`, and `timed("seq_write", …)` respectively. `upload_blob` wraps `state.blobstore.put_permanent(cid, bytes)` with `timed("blob_put", …)`. The same `timed()` helper is used at every other boundary listed above. The route table replaces the no-op `routes()` in `pds/src/xrpc/com/atproto/repo/mod.rs` with a real `.at(...)` chain.

5. **Real `com.atproto.repo.*` write handlers.** The five repo write routes now have full handler bodies:
   - `createRecord` — auth via `AccessStandardIncludeChecks`, `prepare_create` from `pds/src/xrpc/com/atproto/repo/prepare.rs`, `ActorStore::transact` → `process_writes` → `Sequencer::sequence_commit`, returns `CreateRecordOutput { cid, uri }`.
   - `putRecord` — same shape, `prepare_update`.
   - `applyWrites` — dispatches each `ApplyWritesInputRefWrite` to the matching prepare helper, runs one transaction.
   - `deleteRecord` — `prepare_delete`, same transaction.
   - `uploadBlob` — sha-256 of the request body, `put_permanent`, returns `BlobOutput` with `Blob { mimeType, size, ref }`. The body is read via `poem::Body::into_vec()` and the sha-256 is computed explicitly inside the handler (the existing `rsky_common::ipld::sha256_to_cid` takes an already-hashed `Vec<u8>`, not raw bytes).
   - `describeRepo` — auth is optional; returns the user's DID, handle, and collection list.

6. **Subsystem instrumentation outside the request path.** `pds/src/sequencer/mod.rs::request_seq_range` wraps the inner impl with `timed("seq_poll", …)`. `pds/src/sequencer/apalis_worker.rs::run_seq_event_job` wraps the publish body with `timed("seq_publish", …)`. `pds/src/sequencer/outbox.rs::Outbox::events` wraps the backfill/cutover with `timed("outbox_events", …)`. `pds/src/auth/auth_verifier.rs::validate_access_token` wraps the per-request impl with `timed("auth", …)`. `pds/src/blobstore/opendal.rs` wraps `put_temp`, `put_permanent`, `get_bytes`, and `get_stream` with `timed("blob_put", …)` / `timed("blob_get", …)`. `pds/src/actor_store/repo/sql_repo.rs` wraps `get_blocks_impl`, `put_many_impl`, `update_root_impl`, `apply_commit_impl`, and the post-commit cache eviction with `timed("actor_*", …)`; the commit closure additionally records `actor_root_write`, `actor_blocks_put`, and `actor_blocks_delete` per-loop-iteration via `metrics::histogram!` directly.

7. **`cacos_outbox_buffer_lag` populated correctly.** `pds/src/sequencer/outbox.rs` extends `Outbox` with `max_observed: i64` and `fn observe_max(&mut self, seq: i64)`. `Outbox::events` records the maximum seq from the backfill into `max_observed` after the backfill loop, then refreshes `cacos_outbox_buffer_lag` as `max(0, max_observed - self.last_seen)`. `OutboxStream::poll_next` resets the gauge to `0` as the consumer advances past the buffered backfill. The `last_seen` field on the stream is the only truth about consumer progress; it advances only when the stream yields an event to the consumer, not when an event is observed on the broadcast channel. ADR-0008's claim that the gauge is populated is now true.

8. **`tracing-unwrap` adoption at the process-startup boundary.** `pds/Cargo.toml` adds `tracing-unwrap = { workspace = true }`. `pds/src/main.rs` imports `tracing_unwrap::ResultExt` and replaces the two `.expect(...)` calls at Site E (`init_operator` and `poem::Server::run`) with `expect_or_log(...)`. The behavior is identical to the originals: an ERROR event is logged on the global `tracing` subscriber and then the process panics. A new test (`pds/tests/tracing_unwrap_test.rs`) installs a local subscriber around `expect_or_log`, catches the panic with `catch_unwind`, and asserts the error event was emitted.

9. **Test instrumentation support.** `pds/src/auth/auth_verifier.rs` converts the global `ACCOUNT_MANAGER` and `OAUTH_PROVIDER` from `OnceLock<Arc<_>>` to `RwLock<Option<Arc<_>>>`. `register_auth_dependencies` overwrites the value so re-registration does the right thing under repeated test setups. A new `_reset_auth_dependencies_for_tests` test-only helper clears the values. `pds/src/observability/metrics.rs::init_metrics` is now race-safe: the fast path checks `METRICS_HANDLE` for `Some`; the slow path builds a recorder, attempts `set_global_recorder`, and only caches the handle in `METRICS_HANDLE` if our recorder actually won the global slot; losers drop their recorder and return without touching the shared handle. `pds/src/observability/timing.rs`'s reporter test uses the shared global recorder via `init_metrics()` + `render()` instead of building a private recorder (which would race with other tests' private recorders).

## Consequences

- 254 lib tests pass (`cargo test -p cacos-pds --lib`), all integration tests pass (`cargo test -p cacos-pds --tests`), `cargo clippy -p cacos-pds --all-targets -- -D warnings` is clean. The `repo_writes_test.rs` integration suite shares a single `SharedState` (via `OnceLock`) and re-registers the auth dependencies per test via `_reset_auth_dependencies_for_tests`, so the parallel test shuffle does not race on the global auth dependency or the metrics recorder.
- New p99+ tail visibility: `cacos_timing_p999_seconds` and `cacos_timing_max_seconds` appear after one reporter tick. The `timing histogram snapshot` info log includes `p999_ms` and `max_ms`.
- `cacos_timing_seconds{stage="…"}` populates for `auth`, `repo_load`, `repo_write`, `seq_write`, `seq_poll`, `seq_publish`, `outbox_events`, `blob_put`, `blob_get`, `actor_get_blocks`, `actor_root_write`, `actor_blocks_put`, `actor_blocks_delete`, `actor_apply_commit`, `actor_cache_evict`. Reserved for future work: `repo_load`, `repo_write`, `seq_write` for the repo write sub-stages (the XRPC route's `repo_load` / `repo_write` / `seq_write` are the ones emitted today).
- `cacos_outbox_buffer_lag` is now non-negative and tracks the consumer's actual progress. The previous implementation declared the gauge but never set it; the contract from ADR-0008 is now satisfied.
- The `com.atproto.repo.*` write path is real: `createRecord`, `putRecord`, `applyWrites`, `deleteRecord`, `uploadBlob`, and `describeRepo` are wired through the same `prepare` helpers, `ActorStore::transact`, and `Sequencer::sequence_commit` that the rest of the XRPC layer relies on. The `com.atproto.repo` route module is no longer a placeholder.
- `tracing-unwrap` is the recommended replacement for `.expect(...)` at the startup boundary. The audit concluded that adoption is warranted only at Site E (the two `.expect()` calls in `pds/src/main.rs`); the rest of the codebase uses `?` with `anyhow::Error` returns or `PdsError::internal(anyhow::Error)` and does not need unwrap instrumentation.
- Direct deps in `pds/Cargo.toml`: `tracing-unwrap = { workspace = true }`.
- `pub async fn timed` is re-exported from `pds/src/observability/timing.rs` as the canonical way to record a stage observation. The helper is `Send + 'static` only by virtue of the future bound; calls that need to hold a guard across `await` already do so via `tracing::Subscribers`'s `set_default`. The `Inner` factory `once_lock` approach (`std::sync::OnceLock` + `futures::executor::block_on`) is the only pattern that is safe to call from both `#[tokio::test]` and synchronous test fixtures.
- The recorder race in `init_metrics` is the only non-obvious behavior change. Production code (`init_metrics()` from `main.rs`) is called exactly once at startup; the race only matters under test parallelism. The fix does not affect production semantics.
- Pre-existing flake: `sequencer::outbox::tests::events_backfills_from_cursor_then_continues_live` is timing-flaky on machines where two ULIDs land in the same millisecond (the assertion compares `evt.seq()` to the next cursor; ULIDs whose timestamps are equal yield equal `timestamp_ms`). The flake pre-dates this work and is independent of the route. It is documented in ADR-0008.
